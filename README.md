# Raildrop

Type-safe uploads and public delivery for Railway Buckets and Railway CDN.

Raildrop is a community project and is not affiliated with or endorsed by Railway.

## Guarantees

- Railway Bucket credentials stay on the server.
- Upload keys are immutable and generated by the server.
- Public delivery is the default; private and temporary policies are explicit route options.
- Namespace paths are composed from validated segments.
- Upload completion verifies the stored object before callbacks run.
- Upload sessions are encrypted, signed, expiry-bound, and include a verified metadata digest.
- Public gateway responses are suitable for Railway's service-level CDN.

## Environment

Raildrop reads prefixed variables first and Railway bucket variables as a fallback:

```text
RAILDROP_BUCKET / BUCKET
RAILDROP_ENDPOINT / ENDPOINT
RAILDROP_REGION / REGION
RAILDROP_ACCESS_KEY_ID / ACCESS_KEY_ID
RAILDROP_SECRET_ACCESS_KEY / SECRET_ACCESS_KEY
RAILDROP_SECRET
RAILDROP_PUBLIC_BASE_URL
RAILDROP_ALLOWED_ORIGINS
```

`RAILDROP_SECRET` must be an independent random secret with at least 32 characters.

## Railway CDN

Deploy the public gateway as a dedicated Railway service and enable CDN caching for that service.
Do not place authenticated APIs on the same cache-enabled service. Private files should be delivered
through short-lived presigned GET URLs after application authorization.

## CLI

- `raildrop health` verifies bucket credentials.
- `raildrop cors` compares bucket CORS with `RAILDROP_ALLOWED_ORIGINS`.
- `raildrop cors:apply` applies origin-restricted PUT/GET/HEAD CORS and verifies its methods and
  request-header support. Railway requires `AllowedHeaders: ['*']` for browser presigned uploads;
  origins remain an exact allowlist.
- `raildrop sync <manifest.json>` replaces the global manifest with checksum-addressed assets from
  the supplied manifest in every configured bucket.
- `raildrop upsert <manifest.json>` publishes checksum-addressed assets while preserving aliases
  not present in the supplied manifest.
- `raildrop mirror` merges and verifies `public/global/` across all configured buckets. It refuses
  to overwrite conflicting object keys or aliases and never reads or writes outside that prefix.
- `raildrop cleanup` deletes expired temporary objects and old multipart uploads.

Multi-environment commands use the following credential groups. If none are present, commands keep
the single-bucket behavior described above.

```text
RAILDROP_DEVELOPMENT_BUCKET / ENDPOINT / REGION / ACCESS_KEY_ID / SECRET_ACCESS_KEY
RAILDROP_STAGING_BUCKET / ENDPOINT / REGION / ACCESS_KEY_ID / SECRET_ACCESS_KEY
RAILDROP_PRODUCTION_BUCKET / ENDPOINT / REGION / ACCESS_KEY_ID / SECRET_ACCESS_KEY
```

## Rate limiting and scanning

Raildrop validates route policy and storage metadata. Use a route's `.validate(...)` hook for
malware/content scanning before completion. The host application remains responsible for request
rate limits; the Hono adapter intentionally does not impose a storage-agnostic rate-limit policy.

Client multipart uploads retry failed parts, upload parts concurrently, and persist resumable state
when browser local storage is available. Aborting an `AbortSignal` pauses by default; set
`abortOnCancel` to remove the remote multipart upload instead.

Persisted resume keys include the API URL, route input, file content hash, and configured resume
scope. Authenticated applications should provide a dynamic `resumeScope` (for example, the current
session or account identity), and may pass a stable per-upload `resumeKey` such as an attachment ID.

## Why Raildrop

- **Bring your own bucket.** Your S3-compatible bucket credentials stay on your server — no third-party paid plan standing between your app and its files.
- **Type-safe end to end.** Define upload routes once on the server; the client infers endpoint names, inputs, and completion payloads from that exact router.
- **Direct-to-bucket uploads.** Clients upload through presigned PUT or resumable multipart sessions. Your API never proxies file bytes.
- **Encrypted upload sessions.** Session tokens are signed and expiry-bound, with a verified metadata digest, so finalize requests cannot be forged or mutated.
- **Resumable multipart.** Failed parts retry, parts upload concurrently, and progress persists to local storage so interrupted uploads resume.
- **Public delivery by default.** A signed public gateway serves normalized `public/` objects behind your CDN; private files resolve to short-lived presigned GET URLs after your own authorization.

## Inspiration

Raildrop is heavily inspired by [UploadThing](https://uploadthing.com) — its type-safe
upload router DX (define routes on the server, infer everything on the client) is the
developer experience we wanted to keep.

We built Raildrop because UploadThing is a hosted, subscription-based service: your files
flow through and live on third-party infrastructure. We wanted the same end-to-end
type-safe workflow, but backed by **our own S3-compatible bucket** — specifically
[Railway Buckets](https://railway.app) with the Railway CDN — so credentials never leave
the server, there is no per-plan file quota, and direct-to-bucket uploads keep file bytes
out of the API entirely. If you want UploadThing's DX on your own bucket, Raildrop is for you.

## Guarantees

- Bucket credentials stay on the server.
- Upload keys are immutable and generated by the server.
- Public delivery is the default; private and temporary policies are explicit route options.
- Namespace paths are composed from validated segments.
- Upload completion verifies the stored object before callbacks run.
- Upload sessions are encrypted, signed, expiry-bound, and include a verified metadata digest.
- Public gateway responses are suitable for service-level CDNs.

| Server core    | `raildrop/server` | Node 20+, Bun, Deno, Cloudflare Workers (Web `Request`) |

## Quickstart

### 1. Define your upload routes (server)

```ts
// server/upload-router.ts
import { createRaildrop } from 'raildrop/server';

const f = createRaildrop();

export const uploadRouter = {
  avatar: f({ image: { maxFileSize: '4MB', maxFileCount: 1 } })
    .middleware(async ({ req }) => {
      const user = await getSessionUser(req); // your auth
      if (!user) throw new Error('Unauthorized');
      return { userId: user.id };             // becomes route metadata
    })
    .namespace(({ metadata }) => ['users', metadata.userId, 'avatars'])
    .onUploadComplete(async ({ file, metadata }) => {
      await db.users.update(metadata.userId, { avatarKey: file.key });
    }),
};

export type UploadRouter = typeof uploadRouter;
```

Builders available on every route: `.input()`, `.access('public' | 'private')`,
`.retention('permanent' | 'temporary', { ttlSeconds })`, `.middleware()`,
`.namespace()`, `.validate()` (scanning hook), `.onUploadComplete()`, `.onUploadError()`.

### 2. Mount the handler

```ts
// Any runtime that speaks Web Request/Response
import { createRouteHandler, railwayBucketConfigFromEnv } from 'raildrop/server';
import { uploadRouter } from './upload-router';

export const handler = createRouteHandler({
  router: uploadRouter,
  storage: new RailwayBucketStorage(railwayBucketConfigFromEnv()),
  secret: process.env.RAILDROP_SECRET!,          // 32+ random chars
  publicBaseUrl: process.env.RAILDROP_PUBLIC_BASE_URL!,
});
```

With Hono:

```ts
import { Hono } from 'hono';
import { registerRaildropHandler } from 'raildrop/hono';

const app = new Hono();
registerRaildropHandler(app, '/api/upload/*', handler);
```

With Bun: `Bun.serve({ fetch: handler })`. With Workers: `export default { fetch: handler }`.

### 3. Upload from the browser

```ts
// client/uploader.ts
import { genUploader } from 'raildrop/client';
import type { UploadRouter } from '../server/upload-router';

export const { uploadFiles } = genUploader<UploadRouter>({ url: '/api/upload' });

const [file] = await uploadFiles('avatar', {
  input: undefined,
  files: [imageFile],
  onUploadProgress: ({ file, progress }) => setProgress(progress),
});
```

### 4. Or use the React helpers

```ts
import { generateReactHelpers } from 'raildrop/react';
import type { UploadRouter } from '../server/upload-router';

export const { uploadFiles, useRaildrop } = generateReactHelpers<UploadRouter>({
  url: '/api/upload',
});
```

```tsx
const { startUpload, isUploading } = useRaildrop('avatar');

<input
  type="file"
  onChange={async (event) => {
    const file = event.target.files?.[0];
    if (file) await startUpload({ input: undefined, files: [file] });
  }}
/>
```

### 5. React Native / Expo

```ts
import { generateReactNativeHelpers, fileFromExpoAsset } from 'raildrop/expo';
import type { UploadRouter } from '../server/upload-router';

export const { uploadFiles } = generateReactNativeHelpers<UploadRouter>({
  url: `${process.env.EXPO_PUBLIC_API_URL}/api/upload`,
});

// Convert an Expo document/image picker asset before uploading:
const file = await fileFromExpoAsset({ uri, name, mimeType, lastModified });
await uploadFiles('avatar', { input: undefined, files: [file] });
```

### 6. Test without a bucket

```ts
import { createRaildropTestHarness } from 'raildrop/testing';
import { uploadRouter } from '../server/upload-router';

const { storage, handler } = createRaildropTestHarness(uploadRouter);
// drive `handler` with synthetic Requests; inspect `storage.objects`
```

## Public delivery and CDN

Deploy the public gateway as a dedicated service and enable CDN caching for that service.
Do not place authenticated APIs on the same cache-enabled service.

```ts
import { createPublicGatewayHandler } from 'raildrop/server';

const gateway = createPublicGatewayHandler({ storage, publicBaseUrl });
```

Private files bypass the gateway — resolve them after your own authorization to
short-lived presigned GET URLs via `RaildropApi` / `storage.getSignedUrl`.
Public immutable keys use long-lived cache headers; aliases use short caches
with stale-while-revalidate.

## Environment

Raildrop reads prefixed variables first and Railway bucket variables as a fallback:

```text
RAILDROP_BUCKET / BUCKET
RAILDROP_ENDPOINT / ENDPOINT
RAILDROP_REGION / REGION
RAILDROP_ACCESS_KEY_ID / ACCESS_KEY_ID
RAILDROP_SECRET_ACCESS_KEY / SECRET_ACCESS_KEY
RAILDROP_SECRET
RAILDROP_PUBLIC_BASE_URL
RAILDROP_ALLOWED_ORIGINS
```

`RAILDROP_SECRET` must be an independent random secret with at least 32 characters,
and must never reuse a bucket credential. Signed URLs and session tokens must not be
persisted to databases, logs, or analytics.

## Custom storage

Anything that satisfies the `RaildropStorage` interface (presign, multipart, head,
get, put, delete, copy, list, signed URLs) can back Raildrop — `RailwayBucketStorage`
is the bundled S3-compatible implementation.

## CLI

- `raildrop health` verifies bucket credentials.
- `raildrop cors` compares bucket CORS with `RAILDROP_ALLOWED_ORIGINS`.
- `raildrop cors:apply` applies origin-restricted PUT/GET/HEAD CORS and verifies its methods and
  request-header support. Browsers require `AllowedHeaders: ['*']` for presigned uploads;
  origins remain an exact allowlist.
- `raildrop sync <manifest.json>` replaces the global manifest with checksum-addressed assets from
  the supplied manifest in every configured bucket.
- `raildrop upsert <manifest.json>` publishes checksum-addressed assets while preserving aliases
  not present in the supplied manifest.
- `raildrop mirror` merges and verifies `public/global/` across all configured buckets. It refuses
  to overwrite conflicting object keys or aliases and never reads or writes outside that prefix.
- `raildrop cleanup` deletes expired temporary objects and old multipart uploads.

Multi-environment commands use the following credential groups. If none are present, commands keep
the single-bucket behavior described above.

```text
RAILDROP_DEVELOPMENT_BUCKET / ENDPOINT / REGION / ACCESS_KEY_ID / SECRET_ACCESS_KEY
RAILDROP_STAGING_BUCKET / ENDPOINT / REGION / ACCESS_KEY_ID / SECRET_ACCESS_KEY
RAILDROP_PRODUCTION_BUCKET / ENDPOINT / REGION / ACCESS_KEY_ID / SECRET_ACCESS_KEY
```

## Rate limiting and scanning

Raildrop validates route policy and storage metadata. Use a route's `.validate(...)` hook for
malware/content scanning before completion. The host application remains responsible for request
rate limits; the Hono adapter intentionally does not impose a storage-agnostic rate-limit policy.

Client multipart uploads retry failed parts, upload parts concurrently, and persist resumable state
when browser local storage is available. Aborting an `AbortSignal` pauses by default; set
`abortOnCancel` to remove the remote multipart upload instead.

Persisted resume keys include the API URL, route input, file content hash, and configured resume
scope. Authenticated applications should provide a dynamic `resumeScope` (for example, the current
session or account identity), and may pass a stable per-upload `resumeKey` such as an attachment ID.
